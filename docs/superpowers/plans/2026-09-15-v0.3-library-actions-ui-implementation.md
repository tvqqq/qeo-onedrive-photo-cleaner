# v0.3 Library Actions, Albums & Photo Detail Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn Photo Detail into the safe per-photo organization surface: edit local Qeo tags, add a photo to an existing OneDrive Photos album, display source identity metadata, and explicitly move a single photo to the OneDrive Recycle Bin.

**Architecture:** Keep Graph mutations behind server-side services and the existing delegated `Files.ReadWrite` client. Add read-only album discovery with a five-minute in-process cache, make album add idempotent by checking bundle membership before POST, and extend the existing `/api/photos/action` route for explicit album/delete mutations. Single-photo delete reloads local photo/ETag server-side, fetches current Graph state, requires an exact non-null ETag match, issues the existing normal Graph `DELETE`, then records local deletion state. Refactor Photo Detail into isolated Tags, Album, Metadata, Technical, and Danger Zone sections; `PhotosGrid` owns visible client state so successful deletion disappears immediately.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript, Microsoft Graph v1.0, SQLite, Vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-09-15-v0.3-library-actions-ai-tags-design.md`

**Dependencies:** Complete both prior plans first:
- `docs/superpowers/plans/2026-09-15-v0.3-foundation-identity-implementation.md`
- `docs/superpowers/plans/2026-09-15-v0.3-ai-tags-search-implementation.md`

## Global Constraints

- TDD for every Graph/service/UI behavior.
- No permanent-delete endpoint, request path, helper, or UI. The existing Graph client guard must remain unchanged and green.
- Single-photo delete is explicit user intent but still requires server-loaded local ETag + fresh Graph ETag equality. Missing ETags abort.
- `DEMO_MODE=1` blocks album mutation and deletion. Read-only album discovery returns an empty list in demo mode rather than requiring Microsoft auth.
- Album picker lists **existing** albums only; it must never call `createAlbum()`.
- A repeated add to an album is a successful no-op. Detect current membership before POST; do not depend on an undocumented duplicate error code.
- Source identity is best-effort metadata. Never infer upload device from camera model, path, filename, or app heuristics.
- Do not alter exact-duplicate deletion requirements or category album-sync behavior.
- If remote delete succeeds but local persistence fails, return/report the persistence failure; never retry the remote DELETE inside the same request.
- Do not merge to `main` without explicit user approval after final CI.

- [ ] **Step 4: Implement `deleteLibraryPhoto()`**

Interface:

```ts
export interface LibraryDeleteDriveApi {
  getItem(itemId: string): Promise<GraphDriveItem>;
  deleteItem(itemId: string, ifMatch?: string): Promise<void>;
}

export async function deleteLibraryPhoto(
  context: {
    db: AppDatabase;
    drive: LibraryDeleteDriveApi;
    demoMode: boolean;
  },
  photoId: string,
): Promise<{ deleted: true }>;
```

Algorithm:

1. if demo mode, throw immediately;
2. `getPhotoById(db, photoId)` and ensure not locally deleted;
3. require `photo.etag`;
4. `await drive.getItem(photo.driveItemId)`;
5. require exact `remote.eTag === photo.etag`;
6. `await drive.deleteItem(photo.driveItemId, photo.etag)`;
7. after Graph success, open one local `BEGIN IMMEDIATE` transaction;
8. insert `deletion_log` with `randomUUID()` and previous ETag;
9. update `photos` and `drive_nodes` deleted timestamps;
10. commit; rollback local transaction on local failure and propagate error; never re-enter step 6.

## Plan 3 Exit Criteria

- Existing OneDrive albums load through Graph v1.0 and are cached for five minutes.
- Repeated album add is an idempotent no-op based on membership lookup; Library never creates albums.
- Photo Detail supports manual Qeo tags, existing album add, source identities, technical metadata, and explicit delete confirmation.
- Single-photo delete uses only normal Graph DELETE with exact ETag safety and local deletion logging.
- Successful delete removes the photo from the current Library immediately.
- Missing Graph source-device data is omitted and never inferred.
- README documents v0.3 upgrade/backfill without `/data` reset.
- Fresh full tests, lint, typecheck, build, Docker web/core/ML smoke, Gitleaks, and code review are green before PR is presented as ready.
