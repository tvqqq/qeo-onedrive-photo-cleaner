# v0.3 AI Tags & Library Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add persistent local Qeo AI Tags, full-library plus incremental ML tagging, manual tag overrides, and fast SQLite `#tag` search/filtering without blocking the core scan lane.

**Architecture:** Build a separate `src/lib/tags/` subsystem on top of the v3 tables created by Plan 1. Reuse the existing `ZeroShotClassifier` and thumbnail cache, add a `tag-photos` job owned only by the ML lane, and make successful per-photo tag replacement transactional with `photo_tag_state`. Scan completion may enqueue one deduplicated follow-up tag job but never awaits ML inference. Library search parses hashtags from the existing `q` field and composes free text plus one `EXISTS` predicate per active tag, preserving server-side pagination.

**Tech Stack:** TypeScript, SQLite, Transformers.js/CLIP, Next.js 16 App Router, React 19, Vitest.

**Spec:** `docs/superpowers/specs/2026-09-15-v0.3-library-actions-ai-tags-design.md`

**Dependency:** Complete `docs/superpowers/plans/2026-09-15-v0.3-foundation-identity-implementation.md` first. This plan assumes schema v3 and source-identity fields already exist.

## Global Constraints

- TDD: every behavior starts with a focused RED test; do not implement first and backfill tests.
- Tags are not categories. Do not change `categories`, `photo_categories`, category review semantics, or category album sync.
- AI vocabulary is fixed/versioned in code. AI never invents free-form tags; users may create manual tags.
- `tag-photos` belongs only to the `ml` lane. A scan must never wait for CLIP work.
- Use local cached thumbnails and the existing CLIP model only; no cloud vision service and no original-file download solely for tagging.
- User manual add/remove wins over AI retagging.
- `state='removed'` and remote-deleted photos never match Library tag search/counts.
- Do not add a new environment variable for threshold/version. They are code constants whose changes require an explicit tagging-version bump.

- [ ] **Step 6: Implement `runTagPhotosJob()`**

Context:

```ts
export interface TagPhotosJobContext {
  db: AppDatabase;
  drive: ThumbnailDriveApi;
  classifier: {
    initialize(): Promise<void>;
    classify(path: string, candidateLabels: string[]): Promise<ModelScore[]>;
  };
  dataDir?: string;
  warn?: (message: string) => void;
}
```

Algorithm:

1. `ensureAiVocabulary(db)`.
2. `await classifier.initialize()` outside the loop; let startup failure reject.
3. Query `listPhotosNeedingTags(db, env.CLIP_MODEL_ID, TAG_TAXONOMY_VERSION)`.
4. Build candidate prompts once from `TAG_VOCABULARY`.
5. For each photo, get cached thumbnail.
6. On Graph 404 `itemNotFound`, `markDriveItemDeleted()`, progress++, continue.
7. On other Graph errors, rethrow.
8. Call classifier. If this per-image call throws a non-Graph error, call `warn(redactError(error))`, progress++, continue without updating tag state.
9. Select max five known prompts at/above threshold.
10. `replaceAiTagsForPhoto(...)` transactionally.
11. Progress++.

Use `context.warn ?? console.warn` and pass only `redactError(error)` to it.

## Plan 2 Exit Criteria

- `tag-photos` is ML-only and restart-safe through the existing queue.
- Initial and incremental tagging use the same idempotent job.
- Exactly the v1 80-tag vocabulary, version, threshold 0.04, and max-5 policy are code-defined.
- Manual add/remove decisions survive retagging.
- Failed individual inference is retriable and cannot mark stale tag state current.
- `#tag` search uses AND semantics and combines with free text.
- Source identity fields are searchable locally.
- Quick tag counts/filtering use SQLite only.
- Full tests, lint, typecheck, build, and worker smoke are green.
